# nlp_worker 会话记忆与配置变更机制 —— 研究结论

> 2026-09-30 讨论结论落盘。
> 背景：老隋质疑「改一下配置文件记忆就没了不太好吧」，以及
> 「为什么改了模型还会影响记忆？你不是说随意改模型也不会丢记忆吗？」
>
> ⚠️ **本文件为内部研究结论，暂不上传 git**（等老隋指令）。

---

## 一、结论速览（要记住的三句话）

1. **改配置（含改模型）不会"删掉"记忆** —— 记忆本体在 Copilot 侧，`session_id` 是找回它的钥匙。
2. **但当前代码改了配置 = 记忆接不回来** —— 不是 Copilot SDK 接不回，
   是 **nlp_worker 自己在一开始就拒绝/删除了尝试**。
3. **跨模型 resume 到底成不成，目前没有代码证据** —— SDK 是编译后的 `copilot.exe`，
   本地无源码；**必须实测才能定案**。

---

## 二、代码事实（每条有出处）

### 2.1 记忆分层

| 层 | 存哪 | 改配置后 |
|---|---|---|
| 记忆本体（对话内容） | Copilot 会话系统 | **不丢**，`session_id` 仍能指到 |
| 映射（key → session_id） | SQLite `session_mappings` 表 | 看配置变更策略 |
| 钥匙（session_id） | SQLite 映射表里 | **会被删**（`/new` 或 `configuration_change:new`） |

### 2.2 为什么改配置"记忆没了"—— 真正的机制

**触发点** `copilot_runtime.py:1593-1602`：

```python
mapping = self.store.get(key)
if mapping and mapping.config_fingerprint != self.config_fingerprint:
    if self.config.copilot.configuration_change == "new":
        self.store.delete(key)          # ← 直接删映射
        return await self._create(key)  # ← 建全新会话（记忆接不回）
    raise CopilotRuntimeError(
        "session model/MCP/skills/agent configuration changed; "
        "use /new or set configuration_change: new"
    )
```

**要点**：
- 指纹一变，**代码根本不会去试 resume** —— 直接删或报错。
- **这就是「改配置记忆没了」的真正原因**：不是 SDK 接不回来，是 nlp_worker 预先拒绝了。

### 2.3 指纹里卷了太多东西（`copilot_runtime.py:1463-1507` `_build_fingerprint`）

```python
payload = {
    "model": 模型名,
    "reasoning": 推理强度,
    "provider": 服务商(除密钥外全量),
    "working_directory": 工作目录,
    "system_prompt_hash": 系统提示词,
    "skills_hash": 技能,
    "tools": 工具集,
    "permissions": 权限,
    "large_output": 大输出配置,   ← 其实不影响会话
    "artifacts": 工件配置,        ← 其实不影响会话
    "mcp": MCP 服务器列表,        ← 改个地址也触发
}
```

**问题**：改 `max_idle_seconds`（超时）这类运行参数，指纹也变 → 记忆被拒。
**这是误伤** —— 超时跟会话记忆毫无关系。

### 2.4 指纹生成（`_build_fingerprint` 里 MCP 部分）

```python
mcp = {
    name: {
        "config": server.model_dump(exclude={"enabled"}),
        "secret_hash": hashlib.sha256(
            json.dumps(getattr(server, "headers", {}), sort_keys=True).encode()
        ).hexdigest(),
    }
    for name, server in sorted(self.config.mcp_servers.items())
    if server.enabled
}
```

### 2.5 配置项（`copilot_runtime.py:229-230`）

```python
resume_failure: Literal["error", "new"] = "error"
configuration_change: Literal["error", "new"] = "error"
```

**现状只有两档**：报错 / 自动新建。**没有"尽量恢复"这档。**

### 2.6 恢复路径（指纹一致时才走）

```
get_or_create(key)                     copilot_runtime.py:1587
   ├─ 内存有 → 直接用
   ├─ 指纹一致 → _resume(session_id)    :1571-1587
   │     └ resume_session(session_id)    :1573  ← SDK 方法
   └─ 指纹不一致 → 按 configuration_change 删/报错
```

### 2.7 SDK 不可见

`resume_session` 来自 `copilot` 包（`copilot_runtime.py:25` `from copilot import CopilotClient`），
**被打包成 159MB 的 `copilot.exe`**（`nlp_worker/build/copilot-runtime/copilot.exe`），
本地没有源码。

## 四、方案（按优先级，未实施）

### 方案 A：细化指纹（解决 80% 痛点，成本低）

指纹只留「真影响会话兼容性」的字段：

| 保留（改了才触发变更） | 剔除（改了不影响记忆） |
|---|---|
| 模型名 / 推理强度 | `max_idle_seconds` / `response_timeout_seconds` 等超时 |
| provider 类型 | 队列 / 消息长度 / 去重 TTL |
| 工作目录 | 日志 / 存储路径 |
| system_prompt / skills / 工具集 / 权限 | `large_output` / `artifacts` 部分运行参数 |

**效果**：改超时/队列/日志 → 指纹不变 → 记忆无感恢复。
**成本**：只改 `_build_fingerprint()` 一个函数。

### 方案 B：加第三档 `configuration_change: "resume"`（最友好，需实测）

配置变了也**先尝试 resume**，失败再降级：

```
配置变了
   ↓ 不再直接删/报错
先尝试 resume_session(旧 session_id)
   ├─ SDK 成功 → 记忆接回 ✅
   └─ SDK 失败 → 按配置降级（报错 或 新建）
```

**它不依赖「跨模型能不能成」的答案** —— 让 SDK 实测决定，对用户永远最友好。
**⚠️ 风险**：跨模型 resume 可能失败，报错可能不友好，需先实测。

### 方案 C：面板把 `configuration_change` 做成下拉框 + 讲清楚

让用户选：`error`（现状，配置变报错）/ `new`（配置变自动新会话）/
（若做 B）`resume`（尽量恢复）。

配合字段说明：**「改成什么样会丢记忆、什么样不会」** —— 正好符合老隋最初要求的
「每个配置项要清晰」。

## 五、待实测（定案的关键）

本地只有编译后的 `copilot.exe`，无源码。**「跨模型 resume 到底成不成」只能实测：**

```
在测试环境（不用生产工程）：
1. 登录 Copilot，模型 A 开会话、发几句让它记住内容
2. 改配置用模型 B，resume 同一 session_id
3. 问它还记得吗？
   - 记得 → 跨模型可行，指纹不该拦
   - 不记得/报错 → 跨模型确实不行，但至少运行参数不该拦（方案 A 仍有效）
```
