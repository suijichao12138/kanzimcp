# nlp_worker 配置面板

> 可视化配置 + 启停 + 看日志。**给不熟悉 YAML 的人用的。**
>
> 独立工具，跟 nlp_worker.exe 放同一个目录即可，不依赖 deployer。

---

## 这是什么

`config.yaml` 有 60+ 个配置项，不认识 YAML 的人很容易填错 ——
错了还得到启动失败才知道。

这个面板让你**填表单**，并且：

- **分三层**：基础（必填）/ 进阶 / 高级，默认只展开基础
- **每个字段都有说明**：干什么的、填错的后果、示例、默认值 —— 点字段旁的 `?` 看详情
- **保存前校验**：通道名和地址对不对得上、目录存不存在、能不能连通
- **顺便启停**：不用记命令行参数，点按钮启动/停止
- **看日志**：不用去找日志文件

---

## 快速上手

1. 把 `nlp-worker-panel.exe` 和 `nlp_worker.exe` 放**同一个目录**
2. 双击 `nlp-worker-panel.exe`
3. 点右上「浏览…」选你的 `config.yaml`（没有就填路径，会自动新建）
4. 填「基础」页签里的项 → 点「校验」→ 点「保存配置」
5. 点「启动」

## 界面说明

### 顶部

| 元素 | 作用 |
|---|---|
| 配置文件 | 当前编辑的 `config.yaml` 路径，可「浏览…」换 |
| 重载 | 从磁盘重新读一遍（丢弃未保存的修改） |
| ● 状态 | nlp_worker 是否在运行，运行中显示 PID |
| 刷新状态 | 重新查进程 |

### 中间三个页签

| 页签 | 内容 | 说明 |
|---|---|---|
| **基础** | 中继连接、工作目录、模型、权限、MCP | 不填就跑不起来，或必须按你的环境改 |
| **进阶** | 工件下载、对话提示、消息长度、日志 | 默认值通常够用 |
| **高级** | 连接细节、Copilot 行为、存储 | 绝大多数情况不用碰 |

### 底部按钮

| 按钮 | 作用 |
|---|---|
| 校验 | 检查配置有没有错（本地规则） |
| **校验+连通性** | 额外试着连一下中继和 MCP 服务（**推荐先点这个**） |
| 打开配置目录 | 在文件管理器里打开 |
| 看日志 | 弹窗显示 `logs/bridge.log` 末尾 300 行 |
| 停止 / 启动 | 按钮控制进程 |
| 保存配置 | 写回 `config.yaml` |

## 字段怎么看

每个字段旁边有 `?` 按钮，点开显示完整说明：

```
┌─ 最大空闲(秒) ─────────────────────────────┐
│ 500                                        │
│ 默认 300 · 示例 300 · 改了需重启才生效       │
│                                            │
│ 只要 Copilot 还在输出或调工具就自动续期；    │
│ 超过这么久毫无动静才判定卡死。              │
│                                            │
│ ⚠️ 调太小会误杀正在跑的长任务；调太大则真    │
│    卡死也不报错。                           │
│                                            │
│ 取值范围：1 ~ 36000                        │
└────────────────────────────────────────────┘
```

**四类信息分别是：**

| 标记 | 含义 |
|---|---|
| 正文 | **这是干什么的** |
| ⚠️ | **填错的后果** —— 最重要，看一眼能省很多事 |
| 默认值 | 不填会用这个 |
| 生效提示 | 改完要不要重启 |

## 最容易填错的几处（面板会帮你查）

| 项 | 为什么容易错 | 面板怎么帮 |
|---|---|---|
| **中继地址 vs 通道名** | 地址末尾那段必须和通道名**完全一样** | 不一致直接报错 |
| **允许的通道** | 必须包含你的通道名，否则启动就报错 | 自动检查 |
| **X-Kanzi-User** | MCP 的请求头必须等于你的通道名，否则 http 组件返回 403 | 自动比对 |
| **工作目录** | 必须真实存在 | 检查目录 |
| **工件下载** | 启用了就必须填「允许的来源」和「数据目录」 | 自动检查 |

**点「校验+连通性」能提前发现「服务没起来 / IP 填错 / 防火墙拦了」。**

## 连接信息怎么填（重点）

**三个服务端不一定在同一台机器上**，所以每个地址都独立填：

```
中继地址      ws://<中继主机>:58080/<你的通道名>
MCP 服务地址  http://<http主机>:9001/kanzistudio_mcp
工件来源      http://<http主机>:9001  /  http://<飞书桥主机>:8081
```

**都是「主机:端口」按你实际部署的填** —— 面板不做任何假设。

如果中继地址变了（换机器、换端口），改这三处即可：
**中继地址**、**MCP 服务地址**、**工件来源**。

---

## 密钥怎么填才安全

**推荐写环境变量引用，而不是明文：**

```yaml
api_key: ${PATEO_API_KEY}
```

然后在系统环境变量里设 `PATEO_API_KEY`。
这样 `config.yaml` 里就没有密钥，发给别人或传到仓库都不怕。

**面板会提醒你**：如果密钥看起来是明文（长字符串且不以 `${` 开头），
校验时会出一条警告。

## 加新配置项（开发者）

**面板不需要改。** 只改 `schema.py`：

```python
{
  "key": "copilot.model.provider.base_url",   # YAML 里的路径
  "label": "服务地址",                          # 中文名
  "tier": "basic",                             # basic/advanced/expert
  "type": "str",                               # 控件类型
  "example": "https://oneapi.pateo.com.cn/v1",
  "help": "自带模型的服务地址，以 /v1 结尾。",    # 这是干什么的
  "hint": "只在使用非 github 服务商时填。",       # 填错的后果
}
```

**支持的 type：**

| type | 控件 |
|---|---|
| `str` / `path` | 输入框（path 带「…」选目录） |
| `int` / `float` | 数字输入框 |
| `bool` | 勾选框 |
| `enum` | 下拉框（配 `options`） |
| `secret` | 密码框（不回显，留空=不改） |
| `list` | 多行文本框（一行一个） |
| `dict` | `k: v; k: v` 单行（如 headers） |
| `dict_list` | 可增删的条目卡片（如 MCP 服务器列表） |

**这就是「面板不跟着 nlp_worker 改」的实现方式** —— 加配置项只动 schema。

| 文件 | 作用 |
|---|---|
| `panel.py` | 主界面（tkinter） |

| `build_panel.py` | 打包脚本 |

## 常见问题

**❓ 找不到 nlp_worker**

面板会在自己所在目录及上级目录找。把两个 exe 放同一个目录最省事。

**❓ 提示「配置文件不存在」**

正常 —— 首次使用会新建。填完点「保存配置」即可。

**❓ 校验报「连不上中继」**

检查：中继服务起了吗、IP/端口对不对、防火墙是否放行。
**注意「校验」（不带连通性）不会联网，只有「校验+连通性」会。**

**❓ 改了配置要重启吗**

字段详情里会标明。多数需要重启 —— 点「停止」再「启动」。

**❓ 密钥框为什么是空的**

出于安全不回显已保存的密钥。**留空 = 保持原值不变**；要改就直接输入新值。

**❓ 没有 PyYAML 能用吗**

能。`yaml_io.py` 内置了极简解析器兜底，覆盖 `config.yaml` 的全部形态。
但装了 PyYAML 会更稳（面板打包时默认带上）。
