# 博泰 C++/C 编码规范检查手册（合并版）

> 本文件把两份来源规范合并为一份按类型分类的检查依据：`PATEO 仪表组C++&C编码规范Ver0.5.xlsx`（192 条，编号前缀 **YB-**）与 `博泰编码规范_C++.pdf`（32 条，编号前缀 **BT-**），共 **224 条**，两份文档的全部正文内容（含变更履历、概述、术语、示例、规则说明、参考资料、代码模板清单）均已收入本文件，未做删减。

## 0. 使用说明（AI 检查协议）

1. **编号与引用**：`YB-No.x` = 仪表组规范条目；`BT-4.x-n` = 博泰规范条目。审查结论必须带编号，便于回溯原文。
2. **级别**：`必须` = 违反即记问题；`建议` = 记为改进项。仪表组条目原文「默认要求」全部为「是」，按必须处理；若原文措辞本身是「建议/不建议/推荐」，本手册在级别后标注「原文措辞含建议」，按建议处理。
3. **检查顺序**：按类型 1→16 逐类扫描代码；同一处问题只归入最贴切的一个类型，避免重复计数。
4. **输出格式**：`文件:行号 | 编号 | 级别 | 原文条款 | 违规片段 | 修改建议`。无法归入任何条目的发现单列为「其他建议」，不要硬套编号。
5. **冲突处理**：两份规范冲突时，按仪表组规范「1.2 适用范围」执行——客户已明确编码规范则遵守客户规范；有 Base 的代码原则上不改 Base 既有代码，新开发代码遵守本规范；两份都未覆盖的，以公司/研发中心相关规范文件为准。
6. **示例的用法**：每个条目下的「规范示例」「反例」摘自原文，仅用于理解条款；判定是否违规时以「判定依据」的原文条款为准，示例本身不构成新条款。

#### 1. 目的（原文）

软件研发是技术也是艺术，不仅要有一行行的代码，还要有主题思想、想象力。在程序员的工作中，大部分的时间都在阅读和理解代码，好的代码规范能够让代码的概念清晰，增加代码的表达力；那种词不达意的范式会破坏我们思考的连贯性，分散有限的注意力。

'祖传'代码，'几代单传'，无注释，想重构又害怕"一不小心大水冲了龙王庙"…，也从侧面反应出一个好的代码规范的重要性。

编写本规范的目的，就是让开发组各成员形成一定共识，共同遵守已被业界同行证实可行、高效的编程规范，提高工作效率和交付代码质量。

#### 2. 适用范围（原文）

适用于本平台开发的 C++ 代码。特殊情况下，经过技术主管，项目 PM 等集体讨论并允许有其他代码风格的，可不遵循此规范。本规范未涉及的规范，以公司、研发中心相关规范文件为准；

#### 3. 术语（原文）

1. 必须…：编码过程中必须遵守；
2. 建议…：建议按照本规范要求执行；

### 类型 1　通用与命名 · 仪表组规范（YB）

#### YB-No.1　通用规则

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

缩略语应代表原来名称的意义，不丢失可读性。

**说明（原文「规则说明」）**

源自《Google Style》的要求。

- 命名不仅仅是记号，而是清楚说出代表的含义，让人理解、过目不忘。而一般来讲，如果长度允许，不建议对单词缩写，以免降低程序的可读性。但如果命名长度过长，也可以酌情对单词进行缩减；但缩减后的单词不应失去可读性。

> 来源：仪表组规范 · 工作表「规则内容」· 序号 No.1 · C适用：相同

#### YB-No.2　通用规则

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

所有标识符不超过31字符。

**说明（原文「规则说明」）**

- 源自《MISRA C 2004》。
- 不是所有的编译器都支持超过31个字符的标识符，有些编码器会直接报错，有些编译器会自动进行截取－－这会造成即使两个标识符不同，但编译器也认为相同的问题。因此，为了保证移植性和正确性，请不要这样做。

> 来源：仪表组规范 · 工作表「规则内容」· 序号 No.2 · C适用：相同

#### YB-No.3　通用规则

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

标识符不应以大小写、下划线、相近字符进行区分。

**反例（原文「不建议使用的例子」）**

```cpp
int32_t id8_Z5;  与  int32_t id8_2S;
int32_t id9_ZS;  与  int32_t id9_25;
```

**说明（原文「规则说明」）**

- 源自《MISRA  C++ 2008》

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

应遵守一个数据类型定义一次的原则（One Definition Rule）。

**反例（原文「不建议使用的例子」）**

```cpp

int32_t XminusY ( S & s )

// source file file2.cpp
struct S
{
      int32_t y ; // Note order of x and y       exchanged
      int32_t x ;
} ;
void setX ( S & s, int32_t v ) { s.x = v; }
void setY ( S & s, int32_t v ) { s.y = v; }

你可能会惊讶地发现XminusY 的结果是y – x 而不是x – y。
```

**说明（原文「规则说明」）**

- 源自《MISRA  C++ 2008》
- 为了避免问题产生，请遵守该规则。

#### YB-No.124　12. 命名空间

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

全局名字空间只能包括main、名字空间声明和extern “C”声明。

**规范示例（原文「建议采用的例子」）**

```cpp
[正例]
namespace
{
     void f2 ( int32_t ); // Compliant
     int32_t x2 ; // Compliant
}
namespace MY_API
{
     void b2 ( int32_t ); // Compliant
     int32_t x2 ; // Compliant
}
int32_t main () // Compliant
{
}
```

**反例（原文「不建议使用的例子」）**

```cpp
void f1 ( int32_t ) ; // Non-compliant
int32_t x1; // Non-compliant
```

**说明（原文「规则说明」）**

- 源自《MISRA C++ 2008》的要求。
- 在适当的名字空间中命名可以减少查找过程中的名字发现（name found）。

> 来源：仪表组规范 · 工作表「规则内容」· 序号 No.124 · C适用：不同

#### YB-No.125　12. 命名空间

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

不应使用using 指令暴露命名空间的全部内容；如希望使用某名字空间的内容，应采用限定名称方式使用。

**规范示例（原文「建议采用的例子」）**

```cpp
[正例]
namespace NS2
{
      int32_t i2 ;
      int32_t j2 ;
      int32_t k2 ;
}
using NS2 ::j2 // Compliant
```

**反例（原文「不建议使用的例子」）**

```cpp
[反例]
   namespace NS1
{
        int32_t i1 ;
        int32_t j1 ;
        int32_t k1 ;
}
using namespace NS1 ; // Non-compliant
```

**说明（原文「规则说明」）**

- 源自《MISRA C++ 2008》的要求。
- using 指令为名字查找添加额外的范围，在这些范围中的所有标识符都成为可见的，增加了编译器查找到的标识符不符合预期的可能性。而using 声明或全限定名称限制了名字的明确指定，因此是更为安全的用法。

**反例（原文「不建议使用的例子」）**

```cpp

 public:
```

```cpp
   public:
        Derived();
  ~Derived();
 private:
       int *i_pointer;
};

 cout<<”Derived destructor\n”;

   Base *b = new Derived;
```

#### YB-No.112　类的规则

**级别**：必须（原文「默认要求」：是）

**判定依据（原文条目内容）**

为需要动态分配内存的类声明一个拷贝构造函数和一个赋值操作符。

只要类型中存在指针和内存操作, 程序中就会对这个类型的对象进行拷贝和赋值的操作，因此请定义自己拷贝构造函数和赋值操作符函数。

**规范示例（原文「建议采用的例子」）**

```cpp
拷贝构造函数和赋值函数请参照String的拷贝构造函数和赋值函数。

String::String(const String &other) 
{
int length = strlen(other.m_data);
m_data = new char[length+1]; 
strcpy(m_data, other.m_data);
}
// 赋值函数
// 赋值时要考虑以下情况，避免问题的发生。
//1，考虑自己赋值的异常情况，如 a = a;
//2，考虑对被复制对象的原有数据的释放，避免发生内存泄漏。
//3, 其他情况参照规则“在operator=中检查给自己赋值的情况”和“让operator=返回*this的引用”。

String & String::operate =(const String &other) 
{
// (1) 检查自赋值 
if(this == &other)
return *this;
// (2) 释放原有的内存资源 
delete [] m_data;
// （3）分配新的内存资源，并复制内容 
int length = strlen(other.m_data);
m_data = new char[length+1]; 
strcpy(m_data, other.m_data);
// （4）返回本对象的引用 
return *this;
}
```

**反例（原文「不建议使用的例子」）**

**说明（原文「规则说明」）**

- 源自《Effective C++ 条款11》。

默认的拷贝构造函数是Bit拷贝，对于拥有指针的对象会造成内存错误等问题。

```cpp
}
```
