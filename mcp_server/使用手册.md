# kanzi_mcp · mcp_server 使用手册

> 版本：v13
> 更新日期：2026-08-28
> 适用目录：`kanzimcp/mcp_server/`

本手册介绍 mcp_server 的整体架构，以及 `relay_nlp_http` 下四个配套工具
（**relay / http / nlp_copilot / feishu**）的作用、启动方法和部署顺序。

---

## 1. 系统概述

这是一套把 **Kanzi Studio MCP 能力** 通过中继（WebSocket）+ HTTP 通道，开放给
**GitHub Copilot CLI（ACP）** 和 **飞书** 使用的桥接系统。让用户在飞书聊天里发指令，
Copilot 执行并直接调用 Kanzi Studio 做操作，最终把结果（含截图/文件）回传到飞书。

典型的完整调用链：

```
[飞书用户] → feishu_bridge (飞书机器人)
               ↓ nlp_client 槽
          → relay_multi (WebSocket 中继, 58080)
               ↓ nlp_worker 槽
          → nlp_worker_acp (Copilot CLI 执行器)
               ↓ MCP over HTTP (9001)
          → kz_mcp_http (HTTP MCP 服务器)
               ↓ client 槽
          → relay_multi (同一中继)
               ↓ server 槽
          → Kanzi Studio（MCP server 插件）
```

即：**飞书 → 桥 → relay → Copilot → HTTP MCP → relay → Kanzi**。

## 3. 部署拓扑（推荐布局）

- **中继机（内网服务器，如 10.10.118.152）**：跑 `relay_multi`、`kz_mcp_http`、
  `feishu_bridge`（三者同机，relay IP 即本机 IP）。
- **Kanzi 机（Windows 内网）**：跑 Kanzi Studio + MCP 插件，以 `server` 角色连中继。
- **Windows 执行机（可选，可与 Kanzi 机同台）**：跑 `nlp_worker_acp`（Copilot），
  以 `nlp_worker` 角色连中继。

> 关键点：`kz_mcp_http.py` 必须监听 `0.0.0.0:9001`（全接口），这样远程的
> copilot/nlp_worker 才能通过 `<中继机IP>:9001` 连进 MCP；不要只绑 127.0.0.1。

## 4. 工具①：relay —— WebSocket 中继

**作用**：多用户、多角色的 WebSocket 中继中枢。每个用户/通道一个 URL 路径段，
一个通道内维护 4 个角色槽：

| 角色 | 连接方 | 说明 |
|------|--------|------|
| `server`    | Kanzi Studio MCP 插件 | 提供 Kanzi 能力 |
| `client`    | kz_mcp_http / 外部 MCP 客户端 | 与 server 双向直通（裸 MCP JSON-RPC） |
| `nlp_client`| 飞书桥 / 聊天插件 | 发用户自然语言指令 |
| `nlp_worker`| Copilot 执行器 | 执行指令并回结果 |

通道内 `nlp_client ↔ nlp_worker` 双向转发；`server ↔ client` 双向转发。

**启动**：
```bash
python relay_multi.py            # 默认监听 0.0.0.0:58080
# 或直接运行打包 exe（start_realy.bat 内容：relay_multi.exe）
```

**连接地址约定**：`ws://<中继机IP>:58080/<用户名>` —— 路径段即通道（用户名）。
同一条通道只允许 1 个 `nlp_client`，多连会踢掉旧连接。

## 5. 工具②：http —— HTTP MCP 服务器

**作用**：把 relay 的 MCP 通道开放成 **streamable HTTP** MCP 端点，供
copilot（ACP 只支持 http/sse，不支持 stdio）连接。一个常驻进程 + 一个端口服务所有用户，
每个用户对应一个 relay 通道和一个 `client` 槽。

**安全模型**：仅白名单内用户可连；客户端请求必须带 HTTP 头 `X-Kanzi-User: <用户名>`，
名单外或未带头直接 403。

**配置文件 `http/users.json`**：
```json
{
  "users": ["suijichao", "wangtianyu", "wangdong", "zhenghaitao", "lvhuiyuan", "test"]
}
```

**启动**（start.bat）：
```bash
python kz_mcp_http.py --relay-base ws://127.0.0.1:58080 --users users.json --listen 0.0.0.0:9001
```
参数：`--relay-base` 中继地址（必填）、`--users` 白名单文件（必填）、
`--listen` 监听地址（默认 `0.0.0.0:9001`）、`--mcp-timeout` 超时（默认 300）、`--debug`。

**copilot 侧配置示例**（header 带用户名）：
```json
{
  "mcpServers": {
    "kanzi": {
      "type": "http",
      "url": "http://<中继机IP>:9001/mcp",
      "headers": { "X-Kanzi-User": "suijichao" }
    }
  }
}
```

`official_mcp.py` 是官方 Kanzi api-MCP / doc-MCP 的轻量 HTTP 客户端，被本进程
做三端点聚合网关以及 nlp_worker 内置查询共用，无需单独启动。

## 6. 工具③：nlp_copilot —— Copilot CLI 执行器

**作用**：通过 **ACP 协议**（Agent Client Protocol）驱动 `copilot --acp` 常驻会话，
作为聊天执行器：收到中继发来的用户指令 → 交给 copilot 处理 → 回传结果。
支持多轮上下文连续、会话持久化恢复，并让 copilot 直接调用 Kanzi MCP。

**角色**：占 relay 通道的 `nlp_worker` 槽位；copilot 调 Kanzi 的 MCP 强制走
`kz_mcp_http.py`（client 槽），不内置。

**会话持久化**：ACP 会话的 sessionId 保存到当前目录会话配置文件
（如 `.nlp_session.suijichao.json`），下次启动自动恢复上下文。

**启动参数**：
```bash
python nlp_worker_acp.py \
  --relay ws://<中继机IP>:58080/suijichao \
  --mcp-port 9001 \
  --bridge-http http://<中继机IP>:8081/suijichao \
  --cwd D:\suijichao\kanzi\AIBox4
```
| 参数 | 说明 |
|------|------|
| `--relay`      | 中继地址（路径段=通道，**必须与 kz_mcp_http 同通道**） |
| `--copilot`    | copilot 命令（默认 `copilot`） |
| `--cwd`        | copilot 工作目录 |
| `--session-file`| 会话持久化文件路径（默认按 relay 自动生成在 cwd） |
| `--model`      | 指定 copilot 模型（如 gpt-5.6-sol） |
| `--notes`      | 开发笔记文件路径（默认 `<cwd>/开发笔记.md`，每次对话自动追加） |
| `--mcp-port`   | kz_mcp_http 的 HTTP MCP 端口（默认 9001） |
| `--mcp-host`   | kz_mcp_http 所在机器 IP（默认用 relay IP 推导） |
| `--bridge-http`| 桥的 HTTP 文件服务地址，用于文件下载/截图回传（**不配则不回传截图**） |
| `--bridge-open-id` | 回传截图/files 携带的飞书用户 open_id（固定单用户可配；留空由桥路由兜底） |
| `--debug`      | 调试日志 |

**⚠️ 注意**：`--bridge-http` 必须配置，否则截图/文件不往回传；桥启动时自动起 8081 文件服务。

`start_nlp_copilot.bat` 会先注入 PATEO 自建模型环境变量（openai 兼容 / oneapi.pateo.com.cn，
模型 `deepseek-v4-flash-fp8`），退出后自动清空，不会污染全局，然后启动 nlp_worker_acp.exe。

## 7. 工具④：feishu —— 飞书 ↔ Kanzi 桥

**作用**：一个桥进程管理多个飞书机器人（bot），每个机器人独立连各自的 relay 通道，
进而连通各自的 nlp_worker/copilot/Kanzi。支持**多 bot + 热更新**。

**架构**：
```
[用户A] → 机器人A(App_A) ─┐
[用户B] → 机器人B(App_B) ─┤→ 同一个 feishu_bridge 进程
[用户C] → 机器人C(App_C) ─┘   每个机器人 = 独立线程跑 lark-oapi 长连接
                                        + 各自 relay 通道(nlp_client 角色)
                                        + 各自 HTTP 文件服务端口 + inbox
```
桥也承担 **HTTP 文件服务**（默认端口如 8081）：转发下载文件、接收 nlp_worker 回传的
截图 / POST 上传文件 / GET 下载 / 兜底扫描 inbox。

**热更新**：默认每 3s 重读 `feishu_config.json` 的 bots 列表，diff 后自动新增/删除/重启
对应机器人，运行中的其它 bot 不受影响，无需重启桥进程。

**启动**：
```bash
python feishu_bridge.py --config feishu_config.json [--debug]
# start.bat 内容：python feishu_bridge.py --config feishu_config.json
```

**配置文件（feishu_config.json，参考头部注释）**：
```json
{
  "reload": { "enabled": true, "watch_interval_s": 3 },
  "http": { "host": "0.0.0.0" },
  "bots": [
    {
      "name": "hmi-alarm",
      "app_id": "...",
      "app_secret": "...",
      "relay_url": "ws://10.10.118.152:58080/hmi-alarm",
      "http_bind_ip": "10.10.118.152",
      "http_port": 8081,
      "inbox_dir": "inbox_hmi-alarm"
    }
  ]
}
```

**⚠️ 注意**：
- 每个 bot 必须连**各自独立通道**（relay_url 路径段不同），不能共用同一通道
  （relay 每条通道只允许 1 个 nlp_client，共用会把别人踢掉）。
- 每个 bot 的 `http_port` 必须**全局唯一**（用端口路由回对应机器人）。
- 与对应 nlp_worker_acp **必须同通道**；nlp_worker 的 `--bridge-http` 指向该 bot 的 http_port。
- **`http_bind_ip` 要填桥自身可被 nlp 访问的地址（即中继机 IP）**，不是 nlp 的 IP。

**飞书 App 权限要求**：需有 `im:resource` 权限（下载用户文件）+ 发送 file 消息权限。

## 8. 部署顺序（推荐）

1. **起中继**：中继机运行 `relay_multi`（`relay/start_realy.bat`）。
2. **起 HTTP MCP**：中继机运行 `kz_mcp_http`（`http/start.bat`）——client 槽由此控制。
3. **起 Copilot 执行器**：执行机运行 `nlp_worker_acp`（`nlp_copilot/start_nlp_copilot.bat`），
   `--relay` 与 kz_mcp_http 同通道，`--bridge-http` 指向桥文件服务。
4. **起飞书桥**：中继机运行 `feishu_bridge`（`feishu/start.bat`），bot 的 relay_url
   与被控 Kanzi 通道一致。
5. **连通 Kanzi**：Kanzi Studio 插件以 `server` 角色连中继对应通道。

> 调试时可先用**有窗口**版看日志；确认无误后改用**无窗口**版常驻。

## 9. 常见问题

| 现象 | 排查方向 |
|------|----------|
| copilot 连不上 MCP | kz_mcp_http 是否监听 `0.0.0.0:9001`（非 127.0.0.1）；users.json 是否有该用户名；请求是否带 `X-Kanzi-User` 头 |
| 截图/文件不回传 | nlp_worker 是否带 `--bridge-http`；桥是否起 8081；nlp_worker 与桥是否同通道 |
| 一个 bot 把另一个踢下线 | 各 bot 的 relay_url 是否各自独立通道（不能同通道共用一个 nlp_client 槽） |
| 文件服务互相串 | 各 bot http_port 是否全局唯一 |
| nlp_worker 反复断连/不响应 | 检查 copilot 是否以纯聊天模式启动（勿挂 --additional-mcp-config 导致卡死）；确认 relay 在线且通道名一致 |
